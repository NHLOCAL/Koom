# קום | Koom 2.2.1

שעון מעורר ל-Android עם חידה קצרה לעצירת הצלצול, ממשק עברי ובחירת מנגינה לכל שעון. האפליקציה כתובה ב-Kotlin וב-Jetpack Compose.

## כיצד פועלת ההשכמה

Android שומר את ההשכמה באמצעות `AlarmManager.setAlarmClock()` ומפעיל ישירות את `RingService` בעזרת `PendingIntent.getForegroundService()`. התזמון אינו תלוי במסך פתוח או בתהליך אפליקציה שנשאר בזיכרון. שירות השמע פועל בזמן הצלצול בלבד.

כל השכמה שומרת מועד מדויק ומזהה ייחודי באחסון שזמין לפני פתיחת הנעילה. חזרה לאפליקציה ואתחול משחזרים את אותו מועד. עריכה או ביטול מבטלים את המזהה הקודם, כך שאירוע שכבר היה בדרך אינו מפעיל בטעות את השעון החדש.

הצלצול משתמש בערוץ השמע של שעונים מעוררים, ממשיך בלולאה ומציג התראה עם גישה לחידה. פתרון החידה או מחיקת השעון הפעיל עוצרים את הנגינה ומשחררים את המשאבים. שעון חוזר משחזר את ההשכמה הבאה גם אם התהליך הופסק בין קבלת האירוע לרישום התזמון הבא.

### אתחול והשכמה שהוחמצה

- לאחר אתחול נשמר המועד שכבר תוכנן, כולל לפני פתיחת הנעילה הראשונה.
- אם המכשיר חוזר לפעול עד 10 דקות אחרי המועד, ההשכמה יכולה להתחיל מיד. מעבר לכך היא מסומנת כהשכמה שהוחמצה. שעון חד-פעמי נכבה, ושעון חוזר ממשיך למועד הבא.
- צלצול שהתחיל לפני אתחול ניתן לשחזור במשך 10 דקות מתחילתו. צלצול פעיל ללא אתחול ממשיך עד פתרון החידה ואינו נעצר אוטומטית לאחר 10 דקות.
- שינוי שעה או אזור זמן מחשב מחדש את שעות ההשכמה המקומיות. נשמר מרווח של 15 שניות לאירוע שכבר הגיע למועדו, כדי ששינוי השעה לא יבטל מסירה שמתרחשת באותו רגע.
- חלון השחזור בן 10 הדקות הוא החלטת התנהגות של Koom, ולא הבטחה של Android.

## צלילים וחידות

ברירת המחדל היא הרינגטון הרגיל של הטלפון. בכל שעון אפשר לבחור צליל ממבחר המכשיר או קובץ שמע, ולהאזין לתצוגה מקדימה מוגבלת ל-9 שניות.

קובץ נבחר נבדק ומועתק לאחסון פרטי שזמין גם ב-Direct Boot, עד 25MB. קבצים שנבחרו בעורך נשמרים כל עוד הטיוטה פתוחה. סיום העריכה מנקה קבצים שאינם בשימוש בלי לפגוע במנגינות של שעונים אחרים. אם מקור שמע נכשל, האפליקציה מנסה מנגינת פעמונים שכלולה ב-APK ובהמשך את צליל השעון של המערכת. המעבר מטפל גם בשגיאה שמגיעה אחרי תחילת הנגינה.

אפשר לבחור חידת ידע כללי, היגיון, חשבון, סדרה או פאזל תמונה 2×2. ברירת המחדל היא שאלה פשוטה בעברית.

## התקנה ובדיקה במכשיר

חבילת הבדיקה נקראת **קום (בדיקה)**, עם מזהה `top.zekal.koom.beta`. היא מותקנת לצד החבילה המקורית `top.zekal.koom` ומחזיקה רשימת שעונים עצמאית.

1. התקן את APK הבדיקה ופתח את האפליקציה פעם אחת.
2. במסך **הגדרות**, ודא שאפשר לתזמן שעונים מדויקים ושמותר להציג התראות ומסך השכמה מלא. בדוק את עוצמת השמע של **שעונים מעוררים** במכשיר.
3. במסך **בדיקה**, הפעל השכמה בעוד 20 שניות וצא למסך הבית. חזור על הבדיקה עם מסך כבוי.
4. בדוק בנפרד את מנקה הזיכרון של היצרן. אם הוא חוסם השכמות, השתמש בהגדרות ההפעלה האוטומטית והפעילות ברקע שאליהן מכוונת האפליקציה.
5. לתרגול אתחול, קבע שעון רגיל כמה דקות קדימה, אתחל והשאר את המכשיר נעול עד ההשכמה.

יומן **בדיקה** כולל את שלבי `SCHEDULED`, `RECEIVED`, `SERVICE_FOREGROUND`, `AUDIO_STARTED` ואירועי שגיאה. הוא מתעד גם דגם, גרסת Android, מגבלות רקע, עוצמת שעון ובגרסאות נתמכות את סיבת סיום התהליך האחרונה. המידע נשמר מקומית ואינו נשלח לשרת.

חתימת debug אינה מפתח ההפצה המקורי. Android מאפשר עדכון התקנה קיימת רק עם חתימה תואמת. במקרה של אי-התאמה בין שתי חבילות בטא, אין להסיר התקנה שמכילה שעונים חשובים רק כדי לעקוף את הבדיקה. גם חבילת release של האפליקציה המקורית מחייבת את מפתח החתימה המקורי כדי לשמר את נתוניה בעדכון.

## ניקוי זיכרון, עצירה כפויה וטלפון כבוי

סיום תהליך רגיל שונה מ-**Force Stop**. שעון הרשום אצל Android יכול להפעיל מחדש תהליך שנסגר. עצירה כפויה מסמנת שהמשתמש עצר את החבילה ועלולה לבטל את השעונים ולמנוע פעילות עד לפתיחה מחדש. ב-Android 15 מתבטלים גם ה-PendingIntent-ים של חבילה שנעצרת כך.

מנקי זיכרון של יצרנים אינם פועלים באותה צורה בכל מכשיר. ביטול אופטימיזציית סוללה לבדו אינו מוכיח שמותרת הפעלה אוטומטית, או שהמנקה אינו עוצר את החבילה. בדיקות האמולטור אינן מאמתות את התנהגות מנקה הזיכרון במכשיר מסוים.

מסך כבוי ומצב Doze הם מצבי בדיקה נתמכים. כאשר הטלפון כבוי לחלוטין, קוד האפליקציה אינו פועל. השכמה שמדליקה מכשיר כבוי תלויה במימוש RTC וקושחה של היצרן; אין API ציבורי כללי שמאפשר ל-Koom להבטיח אותה.

## בנייה ובדיקות אוטומטיות

דרישות הפרויקט: JDK 17, Gradle 9.6.0, Android SDK platform `android-37.0`, Build Tools 36.0.0. האפליקציה תומכת מ-API 26, עם target 36 ו-compile SDK 37.

```sh
gradle --no-daemon testDebugUnitTest assembleDebug assembleDebugAndroidTest lintDebug
```

ב-[PR הפעיל](https://github.com/NHLOCAL/Koom/pull/1) פועל [תהליך האימות](https://github.com/NHLOCAL/Koom/actions/workflows/android.yml). הוא בונה APK, מריץ בדיקות יחידה ולינט, ואז בדיקות מכשיר ב-API 31 וב-API 35. לאחר בדיקות המכשיר ה-APK מותקן מחדש במפורש, משום שמנוע הבדיקה עשוי להסיר אותו בסיום.

בדיקות מחזור החיים כוללות סגירת תהליך, מסך כבוי עם Doze, ואתחול אמיתי עם PIN לפני פתיחת הנעילה הראשונה. הסקריפט בודק שהשעון המדויק רשום במערכת, שהתהליך נעדר לפני המועד ושמופיעים אירועי הקבלה ותחילת השמע. לאחר אתחול נבדקת גם הופעת `RingActivity` במסך הנעילה. הלוגים, דוחות הבדיקות וצילום המסך נשמרים כתוצרי CI.

פרטי התכנון, מקרי הרגרסיה, גבולות ההוכחה והמקורות הרשמיים נמצאים ב-[תיעוד האמינות](docs/alarm-reliability.md).
